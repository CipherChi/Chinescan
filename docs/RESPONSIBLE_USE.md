# Responsible use

Use ChineScan only for assets and data you own or are explicitly authorized to assess. Keep written scope and authorization records for any later-phase activity. Respect applicable law, service terms, privacy obligations, and rate limits.

Phase 2 code scans operate on local directories and do not execute project code. Built-in rules are heuristic, and every result requires analyst validation. Semgrep uses a local rules file; Trivy uses local caches and disables update/look-up requests. pip-audit and npm audit contact advisory services only when selected with `--allow-network-audits`; those services receive dependency metadata. Malware static analysis reads one local file without executing, copying, or persisting sample bytes. YARA and ClamAV are explicit opt-in local integrations; no network enrichment or dynamic analysis is enabled. Domain assessment requires `--i-own-this-target --operator ...` or a local exact-host authorization file. Its built-in probe resolves the exact hostname, restricts connections to public IPs, limits addresses/requests, uses TLS and HTTP HEAD only, and does not follow redirects or read bodies. Do not treat this posture check as a vulnerability scan or proof that a target is safe. Malware intake/storage, memory analysis, a network service, and incident response are not implemented.
